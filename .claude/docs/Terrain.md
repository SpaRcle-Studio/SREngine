# Террейн (Engine/World) и трава

## Чанки и LOD

- Чанки — листья LOD-октодерева (`SR_MATH_NS::LodOctree`, `Utils/Math/LodOctree.h`). Позиция узла — в единицах чанков LOD0, размер узла `2^level`.
- `TerrainChunkCubeGenerator`: листья в `m_chunks`; ожидающие замены — в `m_replacedChunks`, видимы до загрузки замены + `replaceDelayFrames` кадров (объект сцены начинает рисоваться не в кадр включения — без задержки чанк моргает).
  - Замена готова, только когда меш реально в рендере (`ITerrainChunkData::IsRenderReady`: компонент активен, зарегистрирован, не ждёт перерегистрации). Фиксированной задержки мало: объект из пула остаётся зарегистрированным со старым мешом (`SetEnabled(false)`+`SetEnabled(true)` в одном кадре — no-op), новый меш уходит в перерегистрацию.
  - `replaceDelayFrames` сбрасывается, пока замена не готова (при редактировании замена пересоздаётся каждый кадр, иначе счётчик истекает на предыдущей).
  - Обновлять меш на месте нельзя: `ProceduralMesh::SwapIndices/SetIndexedVertices` перерегистрирует меш, он пропадает на кадр. Перегенерация — всегда в новый чанк.
- Объект сцены (`ITerrainChunkGenerator::AcquireChunkObject`) — только чанкам с геометрией, из пула; сверх `maxFreeObjects` уничтожаются.
- Плотность вокселей только на GPU. Вершина — `TerrainMeshVertex`, 64 байта. `VertexLayoutDescription::AddAttribute` выравнивает атрибуты по 16 байт — CPU-структура должна повторять это паддингами.
- Совмещение LOD (`Density.srsl`): чанк с `lodScale = s` берёт воксель `v` в точке `c * (N - 2) + 1 + (v - 1) * s`; объект сдвинут на `-0.5 * (s - 1) * chunkScale` (`GetChunkWorldPosition`).
- Щели между LOD — юбки (`AddSkirts`): только на боковых гранях с соседом другого LOD (`TerrainChunkCube::GetLodBorders`), с обеих сторон стыка; односторонние, лицом наружу (иначе видны из-под земли); в коллизию не идут (только первые `m_collisionIndicesCount` индексов).
- Коллизия лениво: только LOD0, при входе в зону физики, ≤ `maxPhysicsBuildsPerFrame` за кадр, меш предварительно упрощается meshoptimizer.
- Материалы — интерполируемые веса `MATERIAL_WEIGHTS` (vec4). Целочисленные атрибуты (`MATERIAL_ID*`) генератор GLSL делает `flat` → резкие швы.

## Деформации

- `Terrain::AddDeformation` только кладёт в `m_pendingDeformations`. В `Terrain::LateUpdate` всё за кадр впекается в `m_editBlocks`, очередь чистится, область перегенерируется одним `InvalidateRegion`.
- Правки — добавка к плотности в точках сетки LOD0, блоками `SR_TERRAIN_EDIT_BLOCK_SIZE`^3, только там, где была деформация; переживают выгрузку чанков; кеша вокселей у чанков нет. Со сценой не сериализуются.
- Точка плотности `d` (любой LOD) в мире на `(d - 0.5) * voxelSize`, `voxelSize = chunkScale` (`ITerrainChunkGenerator::GetVoxelSize`). Плотность в вокселях → `strength` (м) делится на размер вокселя.
- Генератор собирает правки для сетки чанка (воксель `v`: `chunkCoord * (N - 2) + 1 + (v - 1) * lodScale`) в SSBO `densityOffsets`, `Density.srsl` прибавляет их. LOD-чанк берёт одну точку LOD0 на воксель.
- `InvalidateRegion`: загруженные чанки — через замену (без моргания), пустые — на месте. Если место ещё занято заменяемым чанком, текущий помечается `IsDirty` и перегенерируется в `ReleaseReplacedChunks`. Выбрасывать нельзя — геометрия моргает, старая висит до конца деформации.

## Трава (TerrainGrass)

- Генерация в `SR_HTYPES_NS::Thread` (тело `WorkerStep`), не `std::thread`. Тело — одна задача за вызов, без блокировок: без `SR_THREADS_ALLOWED` (веб) его зовёт главный цикл через `Thread::Factory::ManuallyUpdateThreads`.
- При генерации отсекаются только травинки дальше `maxDistance + generationMargin`. LOD-кривую (`GetKeepFraction`) при генерации не применять (пока задача в очереди, наблюдатель уходит — вблизи редко); плотность по дистанции применяет рендерер.
- Отход наблюдателя дальше `regenerateDistance` → перегенерация по мешу из `m_sources`. Пока по чанку `isPending`, новую задачу не ставить (иначе при движении трава не появляется).
- `maxInstancesPerChunk` отсекает самые дальние (`nth_element` по дистанции). Не срезать по `rank` (плотность скачет между перегенерациями, «задвоение») и не по порядку треугольников (пустые куски). Чанк — сотни метров, малый лимит заметно разреживает.
- Инстансы в осях объекта чанка; объекты из пула → трава (инстансы и `m_sources`) сбрасывается при каждой смене владельца, иначе двойная плотность. Поэтому `OnChunkGenerated` вызывается для каждого чанка с объектом (LOD > 0 — с пустым мешем), а `ReleaseChunkObject` чистит рендерер травы безусловно.
- Заменённый чанк освобождается только при готовой траве замены (`ITerrainChunk::IsGrassReady`), иначе место голое.
- VBO инстансов нельзя освободить сразу (на него ссылаются закешированные командные буферы других кадров свапчейна) → `FreeRetiredVBOs`. У пустых/выключенных рендереров `Draw()` не вызывается, поэтому освобождение также из `UpdateLod`/`FreeRetired`; такие рендереры лежат в `m_retiredRenderers`.
