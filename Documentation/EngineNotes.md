# Заметки по движку для разработки

Неочевидные вещи, на поиск которых уходит время. Перед правками в этих системах стоит перечитать соответствующий раздел.
Разрешено дополнять в ходе выполнения задач.

## Террейн (Engine/World)

- Чанки — листья LOD-октодерева (`SR_MATH_NS::LodOctree`, `Utils/Math/LodOctree.h`). Позиция узла задаётся в единицах чанков нулевого уровня, размер узла равен `2^level`.
- `TerrainChunkCubeGenerator` хранит листья в `m_chunks`. Чанки, которые ждут замены, лежат в `m_replacedChunks` и остаются видимыми, пока замена не загрузится, плюс ещё `replaceDelayFrames` кадров.
  - Объект сцены начинает рисоваться не в тот кадр, в котором его включили (см. «ECS» ниже). Без этой задержки чанк моргает на один кадр.
  - Обновлять меш на месте тоже нельзя: `ProceduralMesh::SwapIndices/SetIndexedVertices` перерегистрирует меш в рендере, и он пропадает на кадр. Перегенерация всегда идёт в новый чанк.
- Объект сцены (`ITerrainChunkGenerator::AcquireChunkObject`) выдаётся только чанкам с геометрией и переиспользуется через пул. Объекты сверх `maxFreeObjects` уничтожаются.
- Плотность вокселей хранится только на GPU и на CPU не копируется. Вершина меша террейна — `TerrainMeshVertex`, 64 байта.
- `VertexLayoutDescription::AddAttribute` выравнивает каждый атрибут по 16 байт. CPU-структура вершины должна повторять это выравнивание с паддингами.
- Совмещение LOD (`Density.srsl`): для чанка с `lodScale = s` воксель `v` берётся в точке `c * (N - 2) + 1 + (v - 1) * s`, а объект чанка сдвигается на `-0.5 * (s - 1) * chunkScale` (`GetChunkWorldPosition`).
- Щели между LOD закрываются юбками (`AddSkirts`):
  - юбки строятся только на боковых гранях с соседом другого LOD (`TerrainChunkCube::GetLodBorders`), с обеих сторон стыка;
  - юбки односторонние, лицевой стороной наружу, иначе они видны из-под земли;
  - в коллизию юбки не попадают: в неё идут только первые `m_collisionIndicesCount` индексов.
- Коллизия строится лениво: только у LOD0, при входе чанка в зону физики, не больше `maxPhysicsBuildsPerFrame` за кадр. Сначала меш упрощается через meshoptimizer.
- Материалы террейна передаются как интерполируемые веса `MATERIAL_WEIGHTS` (vec4). Целочисленные атрибуты (`MATERIAL_ID*`) генератор GLSL делает `flat`, то есть без интерполяции, поэтому на стыке материалов из них получаются резкие швы.

## Трава (TerrainGrass)

- Генерация идёт в потоке движка (`SR_HTYPES_NS::Thread`, тело `WorkerStep`), а не в `std::thread`. Тело обрабатывает одну задачу за вызов и не должно блокироваться: без `SR_THREADS_ALLOWED` (веб) его вызывает главный цикл через `Thread::Factory::ManuallyUpdateThreads`.
- При генерации отсекаются только травинки дальше `maxDistance + generationMargin` от наблюдателя. Отбирать по LOD-кривой (`GetKeepFraction`) при генерации нельзя: пока задача ждёт в очереди, наблюдатель уходит, и вблизи трава оказывается редкой. Плотность по дистанции применяет рендерер при отрисовке.
- Когда наблюдатель отходит от точки генерации дальше `regenerateDistance`, трава чанка перегенерируется по исходному мешу из `m_sources`. Пока по чанку есть задача в работе (`isPending`), новая не ставится: иначе при движении результат постоянно устаревает и трава так и не появляется.
- `maxInstancesPerChunk` отсекает самые дальние от наблюдателя травинки (`nth_element` по дистанции). Срезать по `rank` нельзя: плотность вблизи падает, а набор зависит от позиции камеры при генерации, и при каждой перегенерации плотность скачет (выглядит как задвоение травы). По порядку треугольников тоже нельзя: часть чанка остаётся пустой. Чанк большой (сотни метров), поэтому маленький лимит заметно разреживает траву.
- Инстансы травы хранятся в осях объекта чанка и рисуются относительно его текущей позиции. Объекты чанков переиспользуются через пул, поэтому трава объекта (инстансы и источник в `m_sources`) должна сбрасываться при каждой смене владельца. Иначе трава прошлого места рисуется на новом поверх своей (двойная плотность). Поэтому `OnChunkGenerated` вызывается для каждого чанка с объектом, а для LOD > 0 — с пустым мешем, и `ReleaseChunkObject` чистит рендерер травы безусловно.
- Заменённый чанк (`m_replacedChunks`) освобождается только когда у замены готова и трава (`ITerrainChunk::IsGrassReady`). Иначе на время генерации новой травы место остаётся голым.
- Буфер инстансов (VBO) нельзя освободить сразу, потому что на него ссылаются закешированные командные буферы других кадров свапчейна. Старые буферы освобождаются в `FreeRetiredVBOs`. У пустых и выключенных рендереров `Draw()` не вызывается, поэтому это делается и из `UpdateLod`/`FreeRetired`. Выключенные рендереры с ещё живыми буферами лежат в `m_retiredRenderers`.

## Рендер

- `RenderQueue` фиксирует VBO в момент регистрации. Изменение меша ставит объект в очередь перерегистрации (`RenderStrategy::Prepare`), и пока объект её ждёт (`IsWaitReRegister`), он не рисуется.
- Compute: `ComputeShader::EndCompute()` вызывает `WaitComputeIdle()`, то есть compute-проход синхронный, и после него SSBO можно читать сразу.
- `SSBOInstance::ResetCounter()` на неоткрытом (не замапленном) буфере сам открывает его, флашит и закрывает. Вызывать после этого `FlushCounter()` без `Map` нельзя: сработает ассерт `SSBO is not mapped`.
- `VertexDataBuffer::GetVertex` определён внутри `#ifdef SR_UTILS_ASSIMP` (`Vertices.cpp`) и в сборках без assimp отсутствует. Надёжнее работать с `data` напрямую по `layout`.

## ECS

- `SceneObject::SetEnabled` только помечает объект грязным. Активность применяется позже, в `CheckActivity`, поэтому компоненты получают `OnEnable` не сразу.

## Физика (PhysX)

- `PhysicsScene::Flush` сначала добавляет тела, потом удаляет. `Register` убирает тело из очереди удаления, чтобы выключение и включение в одном кадре не выкидывали его из сцены.
- `AddRigidbody/RemoveRigidbody` проверяют `pActor->getScene()`. Тело может прийти на удаление повторно: сначала из `OnDisable`, потом из `OnDestroy`.
- `PhysXPhysicsWorld::SynchronizeStatic` кукает не больше `maxCookPerFrame` треугольных мешей за кадр. Позиция статических тел обновляется до проверки лимита, иначе тело, переехавшее из пула, остаётся на старом месте и сквозь него проваливаются.
- Кукинг треугольных мешей (`PhysXCollisionShape::CreateTriangleMesh`): `createTriangleMesh` с insertion callback без сериализации, BVH34 при `PX_SSE2` и `suppressTriangleMeshRemapTable`.

## Шейдеры и кодоген

- В SRSL `int * ivec3` лучше писать как `ivec3(x) * v`: WGSL не делает неявного расширения скаляра.
- Значения тега `@range(...)` вставляются в C++ как выражения. Для float пиши с суффиксом `f`.
- Tracy: `SR_TRACY_ZONE` и `SR_TRACY_ZONE_N` в одной области видимости объявляют одну и ту же переменную. `SR_TRACY_ZONE_N` ставь только во вложенный блок.
